## 1. Overview

MORAl is an annotation-based memoization library for Android and plain JVM projects. It allows developers to cache method results by simply adding `@Memoize` to a method. A Gradle plugin performs ASM bytecode transformation at build time to inject all cache mechanics transparently -- no call-site changes, no wrapper classes, no boilerplate.

**Developer experience:**

```java
// Before: no memoization
public boolean search(int key) { /* expensive traversal */ }
public void insert(int data)   { /* mutates state */ }

// After: add two annotations -- that's it
@Memoize(maxSize = 64)
public boolean search(int key) { /* expensive traversal */ }

@CacheInvalidate
public void insert(int data)   { /* mutates state */ }
```

No changes to callers. No wrapper classes. The build-time transformation handles everything.

**Key design properties:**
- **Transparent**: No call-site changes required. The method signature is unchanged.
- **Java + Kotlin**: Works on Java and Kotlin code, in Android and plain JVM projects (operates at bytecode level).
- **Lightweight**: All cache logic lives in a small runtime library (14 classes). The ASM injection is a thin shell.
- **Correctness-first**: `@CacheInvalidate` clears caches when a mutating method returns. It can clear all caches of the instance, named caches, or single entries.
- **Configurable**: Cache size, eviction policy, TTL, thread safety, stats, and auto-monitoring are all annotation parameters.

## 2. Architecture

The library uses a two-layer architecture:

```
 Source Code          Compile Time              Build Time (AGP or JVM)    Runtime
 ==========          ============              =======================    =======

 @Memoize     --->   KSP validates      --->   ASM transforms     --->   MemoDispatcher
 @CacheInvalidate    (errors/warnings)          bytecode                  checks cache,
                                                (adds fields,             computes on miss,
                                                 injects cache logic)     stores result
```

**Layer 1 -- Compile-time validation (KSP):**
The KSP processor scans for `@Memoize` annotations and emits compile-time errors (void return, abstract method, inline function, non-positive `maxSize`) and warnings (mutable parameter types). It generates no code.

**Layer 2 -- Build-time bytecode transformation (ASM):**
In Android projects, the Gradle plugin hooks into the build pipeline via the AGP Instrumentation API. In other projects, it rewrites the class files after each `JavaCompile` task and after `compileKotlin`. An ASM `ClassVisitor` reads each class, detects annotated methods, and injects:
- `MemoCacheManager` and `MemoDispatcher` fields (static fields for static methods)
- Field initialization in constructors, and at the start of `<clinit>` for static caches
- Cache-check bytecode at method entry
- Cache-store bytecode before method returns
- `cacheManager.invalidateAll()`, `cacheManager.invalidate(String[])`, or `cacheManager.invalidateEntry(String, Object[])` calls in invalidating methods (full, selective, or single-entry invalidation)

All actual cache logic (LRU eviction, key construction, TTL, thread safety) is in the **runtime library**, not in generated bytecode. The bytecode is a thin coordination layer that calls into the runtime.

## 4. Annotations API

### `@Memoize`

**File:** [`memoize-annotations/src/main/java/io/github/sanadlab/annotations/Memoize.java`](MORAl/memoize-annotations/src/main/java/io/github/sanadlab/annotations/Memoize.java)

Marks a method for automatic memoization. The method must have a non-void return type.

```java
@Retention(RetentionPolicy.CLASS)
@Target(ElementType.METHOD)
public @interface Memoize {
    int maxSize() default 128;              // Max cache entries
    long expireAfterWrite() default -1;     // TTL in ms (-1 = no expiry)
    CacheScope scope() default CacheScope.INSTANCE;
    EvictionPolicy eviction() default EvictionPolicy.LRU;
    ThreadSafety threadSafety() default ThreadSafety.CONCURRENT;
    boolean recordStats() default false;    // Track hit/miss rates
    boolean autoMonitor() default false;    // Disable the cache if the hit rate is low
    double minHitRate() default 0.3;        // Hit-rate threshold for autoMonitor
    int monitorWindow() default 100;        // Calls before autoMonitor checks the hit rate
}
```

| Parameter | Default | Description |
|-----------|---------|-------------|
| `maxSize` | 128 | Maximum entries before the eviction policy removes entries |
| `expireAfterWrite` | -1 (disabled) | Time-to-live in milliseconds after a cache entry is written |
| `scope` | `INSTANCE` | `INSTANCE` = per-object cache, `CLASS` = static/shared cache (`CLASS` is not implemented, the plugin ignores `scope`) |
| `eviction` | `LRU` | `LRU` = least recently used. `FIFO` = first in, first out. `LFU` = least frequently used. `NONE` = unbounded. |
| `threadSafety` | `CONCURRENT` | Changes only `LRU` caches. `NONE` = unsynchronized LRU map. `SYNCHRONIZED` and `CONCURRENT` = synchronized LRU map. `FIFO` and `LFU` caches are always synchronized. `eviction = NONE` always uses a `ConcurrentHashMap`. |
| `recordStats` | false | When true, tracks hit/miss/eviction counts via `CacheStats`. `autoMonitor = true` also turns stats on. |
| `autoMonitor` | false | When true, the dispatcher disables the cache if the hit rate is below `minHitRate` after `monitorWindow` calls |
| `minHitRate` | 0.3 | Minimum hit rate (0.0 to 1.0) for `autoMonitor` |
| `monitorWindow` | 100 | Number of calls before `autoMonitor` checks the hit rate |

**Retention is `CLASS`**: The annotation is written into `.class` bytecode (readable by ASM at build time) but not available via runtime reflection. This means it's stripped from the final APK, adding zero runtime overhead.

**Static methods:** A Java static method, a Kotlin top-level function, or a `@JvmStatic` function gets one cache for its class. All threads share this cache. It lives as long as the class. The plugin keeps it in static fields (`__memoStaticCacheManager` and static `__memoDispatcher_*` fields). It sets them up at the start of `<clinit>`. For a `@JvmStatic` function in a companion object, the plugin skips the static bridge that Kotlin makes in the outer class. The cache lives on the companion object. `ThreadSafety.NONE` on a static method makes the plugin print a warning. Static methods in interfaces make the build fail.

**Interface and abstract methods:** The plugin never adds fields to an interface.
- The plugin skips an abstract annotated method because it has no body. For a class that is not Kotlin, it prints a warning.
- The plugin skips Kotlin `$DefaultImpls` classes.
- A Kotlin interface default method is memoized through the annotated copies that Kotlin puts in each implementing class. This works with Kotlin `-Xjvm-default=disable` (the default in Kotlin 2.0 and 2.1, tested with 2.0.21). It also works with the Kotlin 2.2+ default `-jvm-default=enable` (tested with kotlinc 2.4.10). Each instance gets its own cache. A default `@CacheInvalidate` method clears the caches of its own instance. A class that overrides the method without `@Memoize` is not cached.
- Not cached, with no error: Kotlin 2.0 and 2.1 with `-Xjvm-default=all-compatibility` (Kotlin makes no copies). Java classes that implement a Kotlin interface.
- Build error: Java interface default methods. Kotlin `-Xjvm-default=all` or `-jvm-default=no-compatibility`.

### `@CacheInvalidate`

**File:** [`memoize-annotations/src/main/java/io/github/sanadlab/annotations/CacheInvalidate.java`](MORAl/memoize-annotations/src/main/java/io/github/sanadlab/annotations/CacheInvalidate.java)

Marks a mutating method as a cache invalidator. Supports **full invalidation** (all caches), **selective invalidation** (specific methods only), and **structured targets** (one `@Invalidation` directive per cache).

```java
@Retention(RetentionPolicy.CLASS)
@Target(ElementType.METHOD)
public @interface CacheInvalidate {
    String[] value() default {};            // Names of caches to clear fully
    Invalidation[] targets() default {};    // Structured per-cache directives
}
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `value` | `String[]` | `{}` (empty) | Names of `@Memoize` methods whose caches are fully cleared. |
| `targets` | `Invalidation[]` | `{}` (empty) | Structured directives. A directive clears one cache, or it removes one entry by parameter indices or by a key-builder method. See [`@Invalidation`](#invalidation). |

If `value` and `targets` are both empty, all caches of the instance are cleared. On a static method, all static caches of the class are cleared. If both are set, the `value` names are cleared first. Then the `targets` directives run.

**Full invalidation** (no arguments -- clears all caches):
```java
@CacheInvalidate
public void resetAll() { /* clears everything */ }
```

**Selective invalidation** (only named caches are cleared):
```java
// Only invalidates search and length; other caches (e.g., describe) are preserved
@CacheInvalidate({"search", "length"})
public void insert(int data) { /* modifies the data structure */ }

// Only invalidates the describe cache
@CacheInvalidate("describe")
public void updateDescriptions() { /* modifies description data */ }
```

Selective invalidation is a performance optimization: when a class has many memoized methods and a mutation only affects specific cached queries, you avoid unnecessarily clearing unrelated caches.

At the bytecode level:
- No arguments → ASM generates `cacheManager.invalidateAll()`
- With arguments → ASM generates `cacheManager.invalidate(new String[]{"search_297da", "length_8aec2"})`. The plugin changes each name to the method key of every overload with that name (see [Phase 1](#64-phase-1-annotation-scanning)).
- A name that matches no `@Memoize` method of the class fails the build (`MemoizeConfigurationException`). This catches typos. Only a bare `@CacheInvalidate` (no `value` and no `targets`) generates `invalidateAll()`.
- Kotlin interface copies are the one exception. Kotlin copies an interface's `@CacheInvalidate` into each implementing class. If that class overrides the target without `@Memoize`, it has no such cache, so the plugin skips that name. The plugin checks the names on the interface itself, so a typo there still fails the build.

**Static and instance invalidators:**
- An instance method can clear static and instance caches. A bare `@CacheInvalidate` on an instance method clears only the instance caches.
- A static method can clear only static caches. If it names an instance cache, the build fails with `MemoizeConfigurationException`.

### `@Invalidation`

**File:** [`memoize-annotations/src/main/java/io/github/sanadlab/annotations/Invalidation.java`](MORAl/memoize-annotations/src/main/java/io/github/sanadlab/annotations/Invalidation.java)

A structured directive. It is used only inside `@CacheInvalidate(targets = {...})`. Each directive names one `@Memoize` method and tells how to invalidate it.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `method` | `String` | (required) | Simple name of the target `@Memoize` method |
| `allEntries` | `boolean` | `false` | When true, clear the whole target cache |
| `keys` | `int[]` | `{}` | Parameter indices of the enclosing method. Their values rebuild the target cache key. |
| `keyBuilder` | `String` | `""` | Name of a helper method in the same class. Its return value is the target's argument list. |
| `keyBuilderArgs` | `int[]` | `{}` | Parameter indices to pass to the helper. Empty = pass the first N parameters, where N is the helper's parameter count. |

The plugin picks one mode:
1. `allEntries = true` → clear the whole target cache.
2. `keyBuilder` set → call the helper. Use its return value as the key.
3. `keys` set → box the selected parameters. Use them as the key.
4. Nothing set → clear the whole target cache.

Key-builder rules:
- The helper can return `Object[]`. The plugin uses the array as the argument list.
- The helper can return any other value. The plugin puts it in a one-element `Object[]` (boxed if it is a primitive).
- The helper can be an instance or a static method. If the enclosing method is static, the helper must be static. If not, the build fails.

The build fails (`MemoizeConfigurationException`) when `method` is empty, when `method` names no `@Memoize` method of the class, when `keys` and `keyBuilder` are both set, or when the helper does not exist. If several `@Memoize` methods have the same name, the plugin uses the first one.

```java
@CacheInvalidate(targets = {
    @Invalidation(method = "getDocument",      keyBuilder = "docKey"),
    @Invalidation(method = "getDocumentCount", allEntries = true)
})
public void addDocument(Document doc) {
    db.insert(doc);
}

private Object docKey(Document doc) {
    return doc.getId();    // scalar return auto-wrapped into Object[]{doc.getId()}
}
```

At the bytecode level, a full-cache directive generates `cacheManager.invalidate(new String[]{key})`. A `keys` or `keyBuilder` directive generates `cacheManager.invalidateEntry(key, args)`.

### `@InvalidateCacheEntry`

**File:** [`memoize-annotations/src/main/java/io/github/sanadlab/annotations/InvalidateCacheEntry.java`](MORAl/memoize-annotations/src/main/java/io/github/sanadlab/annotations/InvalidateCacheEntry.java)

Removes **one entry** from one `@Memoize` cache. All other entries stay in the cache.

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `method` | `String` | (required) | Simple name of the target `@Memoize` method |
| `keys` | `int[]` | `{}` | Parameter indices of the enclosing method, in the target's argument order. Empty = the target takes no arguments. |

```java
@Memoize
public List<Tag> getTags(int itemId) { /* expensive lookup */ }

// Removes only the getTags(itemId) entry
@InvalidateCacheEntry(method = "getTags", keys = {0})
public void updateTags(int itemId, List<Tag> newTags) { /* write new tags */ }
```

At the bytecode level, ASM generates `cacheManager.invalidateEntry("getTags_74d6a", new Object[]{ Integer.valueOf(itemId) })` before each return.

Rules:
- The annotation is not repeatable.
- If several `@Memoize` methods have the same name, the plugin uses the first one.
- If `method` names no `@Memoize` method of the class, the build fails.
- The plugin boxes each selected parameter with its declared type. If this does not match the key of the target cache, nothing is removed.
- An index out of range leaves a `null` slot in the key. Then nothing is removed.
- The same method can also have `@CacheInvalidate`. Both take effect: the plugin adds the `@InvalidateCacheEntry` as one more single-entry directive of the `@CacheInvalidate`.

### `@CacheKey`

**File:** [`memoize-annotations/src/main/java/io/github/sanadlab/annotations/CacheKey.java`](MORAl/memoize-annotations/src/main/java/io/github/sanadlab/annotations/CacheKey.java)

Specifies which field of a complex parameter to use for cache key construction.

```java
@Memoize
public Route findRoute(@CacheKey("id") Location start, @CacheKey("id") Location end) {
    // Only start.id and end.id are used as cache keys
}
```

> **Note:** `@CacheKey` field extraction is defined in the annotation API but not yet implemented in the ASM transformation. Currently, entire parameter objects are used as keys via `Arrays.deepHashCode`/`Arrays.deepEquals`. See [Limitations](#11-current-limitations).

## 5. Runtime Library

The runtime library provides the cache infrastructure that the ASM-injected bytecode calls into. All classes are in the `io.github.sanadlab.runtime` package.

### 5.1 `MemoCache<K, V>` (Interface)

**File:** [`memoize-runtime/.../MemoCache.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/MemoCache.java)

```java
public interface MemoCache<K, V> {
    V get(K key);
    void put(K key, V value);
    void remove(K key);
    void clear();
    int size();
}
```

### 5.2 `LruMemoCache<K, V>`

**File:** [`memoize-runtime/.../LruMemoCache.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/LruMemoCache.java)

LRU cache backed by `LinkedHashMap` with access-order iteration. When size exceeds `maxSize`, the least recently accessed entry is evicted.

```java
// Internal: LinkedHashMap with access-order and removeEldestEntry override
new LinkedHashMap<K, V>(Math.min(maxSize, 16), 0.75f, true) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        boolean shouldRemove = size() > maxSize;
        if (shouldRemove && stats != null) stats.recordEviction();
        return shouldRemove;
    }
};
```

Thread safety is via `synchronized` methods. All `get`, `put`, `remove`, `clear`, and `size` operations are synchronized.

### 5.3 `ConcurrentMemoCache<K, V>`

**File:** [`memoize-runtime/.../ConcurrentMemoCache.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/ConcurrentMemoCache.java)

Unbounded cache backed by `ConcurrentHashMap`. Lock-free reads, bucket-level write locks. No automatic eviction.

### 5.4 `CacheKeyWrapper`

**File:** [`memoize-runtime/.../CacheKeyWrapper.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/CacheKeyWrapper.java)

Wraps method arguments (`Object[]`) into a proper cache key with correct `hashCode()`/`equals()` semantics.

```java
public final class CacheKeyWrapper {
    public static final CacheKeyWrapper EMPTY = new CacheKeyWrapper(new Object[0]);

    private final Object[] args;
    private final int hashCode;

    public CacheKeyWrapper(Object[] args) {
        this.args = args;
        this.hashCode = Arrays.deepHashCode(args);  // handles nested arrays, nulls
    }

    @Override
    public boolean equals(Object obj) {
        if (this == obj) return true;
        if (!(obj instanceof CacheKeyWrapper)) return false;
        return Arrays.deepEquals(this.args, ((CacheKeyWrapper) obj).args);
    }
}
```

Key design decisions:
- Uses `Arrays.deepHashCode`/`Arrays.deepEquals` to handle primitives, objects, nested arrays, and nulls uniformly.
- Pre-computes hash code in constructor (immutable after creation).
- `EMPTY` singleton for zero-argument methods avoids allocation.

### 5.5 `MemoDispatcher`

**File:** [`memoize-runtime/.../MemoDispatcher.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/MemoDispatcher.java)

The core class that the ASM-injected bytecode calls. Each `@Memoize` method gets one `MemoDispatcher` per object. A static `@Memoize` method gets one `MemoDispatcher` per class.

**Key methods called by ASM bytecode:**

```java
// 0. Create the dispatcher (called from constructors and from <clinit>)
public static MemoDispatcher create(String methodName, int maxSize, long expireAfterWriteMs,
                                    String eviction, String threadSafety, boolean recordStats)
// Used when autoMonitor = true:
public static MemoDispatcher create(String methodName, int maxSize, long expireAfterWriteMs,
                                    String eviction, String threadSafety, boolean recordStats,
                                    boolean autoMonitor, double minHitRate, int monitorWindow)

// 1. Build a cache key from boxed method arguments
public CacheKeyWrapper buildKey(Object[] args)

// 2. Check cache for a hit (returns cached value, NULL_SENTINEL, or null for miss)
public Object getIfCached(CacheKeyWrapper key)

// 3. On a miss: start time for the compute metrics (0 when timing is off)
public long computeStart()

// 4. Store a computed result. Records the compute time when computeStart != 0.
public Object putInCache(CacheKeyWrapper key, Object result, long computeStart)

// 5. Unwrap NULL_SENTINEL back to null
public static Object unwrap(Object cached)
```

`MemoCacheManager` calls `invalidate()` (clear all entries) and `invalidateEntry(Object[] args)` (remove one entry).

**Cache selection:** The dispatcher picks the cache class from `eviction` and `threadSafety`:

| `eviction` | `threadSafety` | Cache class |
|------------|----------------|-------------|
| `LRU` | `NONE` | `UnsynchronizedLruMemoCache` |
| `LRU` | `SYNCHRONIZED` or `CONCURRENT` | `LruMemoCache` (synchronized) |
| `FIFO` | any | `FifoMemoCache` (synchronized) |
| `LFU` | any | `LfuMemoCache` (synchronized) |
| `NONE` | any | `ConcurrentMemoCache` (unbounded) |

**Null handling via sentinel pattern:**

A critical design issue: how to distinguish "the cache has no entry for this key" (miss) from "the cache has an entry whose value is null" (hit). The `MemoDispatcher` uses a sentinel object:

```java
private static final Object NULL_SENTINEL = new Object();

// In putInCache:
Object toStore = result != null ? result : NULL_SENTINEL;
cache.put(key, toStore);

// In getIfCached:
Object cached = cache.get(key);
if (cached != null) {
    if (stats != null) stats.recordHit();
    return cached;   // caller must call unwrap() to convert sentinel back to null
}
if (stats != null) stats.recordMiss();
return null;         // null means "cache miss"
```

**TTL support:**

When `expireAfterWrite > 0`, the dispatcher maintains a parallel timestamp cache. On `getIfCached()`, it checks if the entry has expired:

```java
if (timestamps != null) {
    Long writeTime = timestamps.get(key);
    if (writeTime != null) {
        long elapsed = System.nanoTime() - writeTime;
        if (elapsed > expireAfterWriteMs * 1_000_000L) {
            // Expired: remove the entry and report a miss
            cache.remove(key);
            timestamps.remove(key);
            if (stats != null) stats.recordMiss();
            return null;
        }
    }
}
```

**Auto-monitor:**

When `autoMonitor = true`, `putInCache()` checks the hit rate after each store. If the request count is at least `monitorWindow` and the hit rate is below `minHitRate`, the dispatcher disables the cache. It also clears the cache. After that, `getIfCached()` always returns null and `putInCache()` stores nothing. `reenable()` turns the cache on again and resets the stats.

### 5.6 `MemoCacheManager`

**File:** [`memoize-runtime/.../MemoCacheManager.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/MemoCacheManager.java)

Manages all `MemoDispatcher` instances for a single object, or for the static caches of a class. The ASM transformation adds an instance field `__memoCacheManager` for instance caches. It adds a static field `__memoStaticCacheManager` for static caches. A class can have both.

```java
public final class MemoCacheManager {
    private final ConcurrentHashMap<String, MemoDispatcher> dispatchers = new ConcurrentHashMap<>();

    public void register(String methodName, MemoDispatcher dispatcher) { ... }
    public MemoDispatcher getDispatcher(String methodName) { ... }

    // Called by @CacheInvalidate (no args) -- clears ALL caches
    public void invalidateAll() {
        for (MemoDispatcher dispatcher : dispatchers.values()) {
            dispatcher.invalidate();
        }
    }

    // Called by @CacheInvalidate({"search", "length"}) -- selective invalidation
    public void invalidate(String[] methodNames) {
        for (String name : methodNames) {
            MemoDispatcher dispatcher = dispatchers.get(name);
            if (dispatcher != null) {
                dispatcher.invalidate();
            }
        }
    }

    // Called by @InvalidateCacheEntry and @Invalidation(keys/keyBuilder) -- one entry
    public void invalidateEntry(String methodKey, Object[] args) {
        MemoDispatcher dispatcher = dispatchers.get(methodKey);
        if (dispatcher != null) {
            dispatcher.invalidateEntry(args);
        }
    }
}
```

The plugin registers each dispatcher under its method key, not under the plain method name. The method key is the method name plus a 5-hex-digit hash of the name and descriptor, for example `search_297da`. The plugin also passes method keys to `invalidate(String[])` and `invalidateEntry(...)`.

The manager supports three modes:
- **Full invalidation** (`invalidateAll()`): clears every cache. Used when `@CacheInvalidate` has no arguments.
- **Selective invalidation** (`invalidate(String[])`): clears only the named caches. Used when `@CacheInvalidate({"method1", "method2"})` specifies targets. The manager ignores unknown keys. The plugin never passes one, because a name that matches no `@Memoize` method fails the build.
- **Single-entry invalidation** (`invalidateEntry(String, Object[])`): removes one entry from one cache. Used by `@InvalidateCacheEntry` and by `@Invalidation` with `keys` or `keyBuilder`. Unknown keys are silently ignored.

The manager also has `getDispatchers()`, `totalSize()`, `dumpReport()`, and `logReport()` for debugging.

### 5.7 `CacheStats`

**File:** [`memoize-runtime/.../CacheStats.java`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/CacheStats.java)

Thread-safe statistics tracker using `AtomicLong` counters:

```java
public final class CacheStats {
    private final AtomicLong hitCount = new AtomicLong();
    private final AtomicLong missCount = new AtomicLong();
    private final AtomicLong evictionCount = new AtomicLong();

    public double getHitRate() {
        long requests = hitCount.get() + missCount.get();
        return requests == 0 ? 0.0 : (double) hitCount.get() / requests;
    }
}
```

Stats are only tracked when `@Memoize(recordStats = true)` or `@Memoize(autoMonitor = true)` is set. When both are false (the default), the `stats` field is `null` and all stat-recording calls are skipped.

### 5.8 Other cache implementations

- [`FifoMemoCache`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/FifoMemoCache.java): `LinkedHashMap` in insertion order. A hit does not change the order. When the cache is full, the oldest inserted entry is evicted. Synchronized methods.
- [`LfuMemoCache`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/LfuMemoCache.java): Counts how often each key is used. When the cache is full, the least frequently used entry is evicted. Ties go to the oldest entry. Synchronized methods.
- [`UnsynchronizedLruMemoCache`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/UnsynchronizedLruMemoCache.java): The same LRU behavior as `LruMemoCache`, without locks. Used for `threadSafety = NONE`.

### 5.9 Logging and metrics

- [`MemoLogger`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/MemoLogger.java): Static logging facade. The default level is `OFF`. Set the level with `MemoLogger.setLevel(...)`. On Android, it writes to Logcat. Otherwise, it writes to `System.err`. Install another destination with `MemoLogger.setSink(...)`.
- [`LogLevel`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/LogLevel.java): `OFF`, `ERROR`, `WARN`, `INFO`, `DEBUG`, `TRACE`.
- [`LogSink`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/LogSink.java): Interface for a log destination.
- [`MemoMetrics`](MORAl/memoize-runtime/src/main/java/io/github/sanadlab/runtime/MemoMetrics.java): Per-dispatcher timing. It records data only when the log level is `INFO` or more. `getIfCached()` records the lookup time of each hit. On a miss, the generated code calls `computeStart()`, and the three-argument `putInCache(key, value, start)` records the compute time. With logging off, `computeStart()` returns 0 after one volatile read, and nothing is recorded.

## 6. Build-Time Bytecode Transformation (ASM)

This is the core mechanism that makes `@Memoize` transparent. In Android projects, the transformation runs during the build via the AGP Instrumentation API. In plain JVM projects, it runs right after compilation.

### 6.1 Plugin Registration

**File:** [`memoize-gradle-plugin/.../MemoizePlugin.kt`](MORAl/memoize-gradle-plugin/src/main/kotlin/io/github/sanadlab/plugin/MemoizePlugin.kt)

```kotlin
// Simplified from MemoizePlugin.kt
class MemoizePlugin : Plugin<Project> {
    override fun apply(project: Project) {
        if (applyAndroid(project)) return   // Android project: use the AGP Instrumentation API
        applyJvm(project)                   // Other projects: transform class files after compilation
    }

    private fun applyAndroid(project: Project): Boolean {
        // Returns false if AGP is not on the classpath (found by reflection)
        // or the project has no AndroidComponentsExtension.
        ...
        androidComponents.onVariants { variant ->
            variant.instrumentation.transformClassesWith(
                MemoizeClassVisitorFactory::class.java,
                InstrumentationScope.PROJECT   // Only transform project classes, not dependencies
            ) {}
            variant.instrumentation.setAsmFramesComputationMode(
                FramesComputationMode.COMPUTE_FRAMES_FOR_INSTRUMENTED_METHODS
            )
        }
        return true
    }

    private fun applyJvm(project: Project) {
        project.afterEvaluate {
            // Every JavaCompile task (compileJava, compileTestJava, ...)
            project.tasks.withType(JavaCompile::class.java).configureEach { compileTask ->
                compileTask.doLast {
                    transformClassesInDirectory(compileTask.destinationDirectory.asFile.get(), project)
                }
            }
            // Kotlin main source set only
            project.tasks.findByName("compileKotlin")?.doLast {
                transformClassesInDirectory(
                    project.layout.buildDirectory.dir("classes/kotlin/main").get().asFile, project)
            }
        }
    }
}
```

**Android mode:** This registers the `MemoizeClassVisitorFactory` to be called for every `.class` file in the project during the `transformDebugClassesWithAsm` / `transformReleaseClassesWithAsm` Gradle task.

**JVM mode:** After each `JavaCompile` task and after `compileKotlin`, the plugin rewrites the class files in place. `JvmBytecodeTransformer` runs the same `MemoizeClassVisitor` on each file.
- It skips classes in the `io.github.sanadlab.runtime` and `io.github.sanadlab.annotations` packages.
- It skips a class whose bytes do not contain the `Memoize` or `CacheInvalidate` annotation names.
- It skips a class that already has `__memoCacheManager` or `__memoStaticCacheManager`. So incremental compilation does not transform a class twice.
- A `MemoizeConfigurationException` fails the build. Any other error prints a warning and leaves the class unchanged.
- It does not transform Kotlin test sources (`compileTestKotlin`) or Kotlin Multiplatform JVM targets.

### 6.2 Class Filtering

**File:** [`memoize-gradle-plugin/.../MemoizeClassVisitorFactory.kt`](MORAl/memoize-gradle-plugin/src/main/kotlin/io/github/sanadlab/plugin/MemoizeClassVisitorFactory.kt)

```kotlin
override fun isInstrumentable(classData: ClassData): Boolean {
    val className = classData.className
    return !className.startsWith("android.") &&
           !className.startsWith("androidx.") &&
           !className.startsWith("kotlin.") &&
           !className.startsWith("java.") &&
           !className.startsWith("io.github.sanadlab.runtime.") &&
           !className.startsWith("io.github.sanadlab.annotations.")
}
```

All project classes are visited (since AGP's `ClassData` doesn't expose method-level annotations). The `MemoizeClassVisitor` checks for annotations inside and passes through unmodified classes that have none.

In JVM mode, this factory is not used. `JvmBytecodeTransformer` does the filtering (see [6.1](#61-plugin-registration)).

### 6.3 Two-Pass Transformation Strategy

**File:** [`memoize-gradle-plugin/.../MemoizeClassVisitor.kt`](MORAl/memoize-gradle-plugin/src/main/kotlin/io/github/sanadlab/plugin/MemoizeClassVisitor.kt)

The transformation uses the ASM **tree API** (`ClassNode`) for a two-pass approach:

```
Pass 1 (Tree API):
  Read class into ClassNode
  → If the class already has a manager field: pass it through unchanged
  → Scan all methods for @Memoize / @CacheInvalidate / @InvalidateCacheEntry annotations
    (skip Kotlin @JvmStatic bridges, Kotlin $DefaultImpls classes, and abstract methods)
  → Collect metadata (method names, descriptors, all @Memoize parameters except scope)
  → Resolve invalidation targets to method keys (a name that matches no @Memoize method fails the build)
  → Add an @InvalidateCacheEntry to the @CacheInvalidate of the same method, if there is one
  → Add MemoCacheManager + MemoDispatcher fields (static fields for static methods)
  → Patch constructors (insert initialization before RETURN)
  → Patch <clinit> (insert static initialization at the start)
  → Write modified ClassNode to bytes

Pass 2 (Visitor API):
  Re-read modified bytes
  → For @Memoize methods: inject cache-check at entry, cache-store at exit
  → For @CacheInvalidate methods: inject invalidateAll() (bare annotation only) or
    invalidate(String[]) at exit, then one block for each @Invalidation target and for
    an @InvalidateCacheEntry on the same method
  → For @InvalidateCacheEntry methods: inject invalidateEntry(String, Object[]) at exit
  → Write to next ClassVisitor (output)
```

**Why two passes?** The single-pass visitor pattern processes methods in file order. Constructors (`<init>`) appear before other methods, but we need to know which methods are memoized to generate the correct constructor initialization. The tree API lets us scan all methods first, then patch the constructor with full knowledge.

**Build errors.** The plugin throws `MemoizeConfigurationException`, and the build fails, when:
- A static `@Memoize` method or a static invalidator is in an interface.
- An interface default method has `@Memoize` or an invalidator, and Kotlin makes no copies in the implementing classes (see [Interface and abstract methods](#memoize)).
- A static invalidator names an instance cache.
- A static invalidator uses an instance `keyBuilder` method.
- A name in `@CacheInvalidate(value)`, `@Invalidation(method)` or `@InvalidateCacheEntry(method)` matches no `@Memoize` method of the class. For a Kotlin interface, the plugin checks the names on the interface itself. In Kotlin's copies of the interface methods, it skips a target that the class does not memoize.
- An `@Invalidation` has no `method`, sets both `keys` and `keyBuilder`, or names a `keyBuilder` that does not exist.

**Warnings.** The plugin prints a warning to `System.err`, and the build continues, when:
- An abstract method in a class that is not Kotlin has `@Memoize` or an invalidator.
- A static `@Memoize` method uses `ThreadSafety.NONE`.

### 6.4 Phase 1: Annotation Scanning

```kotlin
// Simplified from MemoizeClassVisitor.visitEnd()
for (method in classNode.methods) {
    if (isKotlinCompanionBridge(method)) continue   // the companion copy holds the cache
    val allAnnotations = (method.visibleAnnotations.orEmpty()) + (method.invisibleAnnotations.orEmpty())
    val isStatic = (method.access and Opcodes.ACC_STATIC) != 0
    if (isKotlinDefaultImpls) continue
    if ((method.access and Opcodes.ACC_ABSTRACT) != 0) continue   // no body to instrument
    for (ann in allAnnotations) {
        when (ann.desc) {
            "Lio/github/sanadlab/annotations/Memoize;" -> {
                // Read maxSize, expireAfterWrite, eviction, threadSafety, recordStats,
                // autoMonitor, minHitRate, monitorWindow. The scope parameter is not read.
                ...
                val key = methodKey(method.name, method.desc)
                memoizedMethods.add(MemoMethodInfo(method.name, method.desc, key, maxSize,
                    expireAfterWrite, eviction, threadSafety, recordStats,
                    autoMonitor, minHitRate, monitorWindow, isStatic))
            }
            "Lio/github/sanadlab/annotations/CacheInvalidate;" -> {
                // Read value (names) and targets (@Invalidation directives)
            }
            "Lio/github/sanadlab/annotations/InvalidateCacheEntry;" -> {
                // Read method and keys
            }
        }
    }
}

fun methodKey(name: String, descriptor: String): String {
    val hash = (name + descriptor).hashCode() and 0xFFFFF // 20 bits = 5 hex digits
    return "${name}_${"%05x".format(hash)}"
}
```

The annotation descriptor format (`Lio/github/sanadlab/annotations/Memoize;`) is the JVM internal name. Annotation values are stored as alternating name-value pairs in the ASM tree model. An enum value (`eviction`, `threadSafety`) is stored as a two-element array: the enum descriptor and the constant name. The plugin keeps the constant name.

The method key makes overloads unique. For example, `search(I)Z` gets the key `search_297da`. A `@CacheInvalidate` name matches every overload with that name. An `@Invalidation` or `@InvalidateCacheEntry` name matches the first overload only.

### 6.5 Phase 2: Field Addition

For the test app's `LinkedList` (`search()`, `length()`, and `describe()` memoized):

```kotlin
// Add: private MemoCacheManager __memoCacheManager;
classNode.fields.add(FieldNode(ACC_PRIVATE | ACC_SYNTHETIC, "__memoCacheManager", ...))

// Add: private MemoDispatcher __memoDispatcher_search_297da;
classNode.fields.add(FieldNode(ACC_PRIVATE | ACC_SYNTHETIC, "__memoDispatcher_search_297da", ...))

// Add: private MemoDispatcher __memoDispatcher_length_8aec2;
classNode.fields.add(FieldNode(ACC_PRIVATE | ACC_SYNTHETIC, "__memoDispatcher_length_8aec2", ...))

// Add: private MemoDispatcher __memoDispatcher_describe_a1647;
classNode.fields.add(FieldNode(ACC_PRIVATE | ACC_SYNTHETIC, "__memoDispatcher_describe_a1647", ...))
```

For static caches, the plugin adds `private static MemoCacheManager __memoStaticCacheManager` and `private static` dispatcher fields (`ACC_STATIC` is added).

The instance manager is added when the class has an instance `@Memoize` method or a bare `@CacheInvalidate` on an instance method. The static manager is added when the class has a static `@Memoize` method or a bare `@CacheInvalidate` on a static method. A named target always has a cache of its kind, so its manager already exists. So an instance method that clears only static caches does not give each instance an empty manager. The plugin never adds fields to an interface.

Fields are marked `ACC_SYNTHETIC` so they don't appear in IDE auto-complete or Javadoc.

### 6.6 Phase 3: Constructor Patching

Before every `RETURN` instruction in every constructor, the following bytecode is inserted:

```java
// Equivalent Java (ASM generates the bytecode instructions directly):
this.__memoCacheManager = new MemoCacheManager();

this.__memoDispatcher_search_297da = MemoDispatcher.create(
    "search_297da", 64, -1L, "LRU", "CONCURRENT", false);
this.__memoCacheManager.register("search_297da", this.__memoDispatcher_search_297da);

this.__memoDispatcher_length_8aec2 = MemoDispatcher.create(
    "length_8aec2", 16, -1L, "LRU", "CONCURRENT", false);
this.__memoCacheManager.register("length_8aec2", this.__memoDispatcher_length_8aec2);
// ... the same for describe_a1647
```

The arguments of `create(...)` are the method key and the `@Memoize` values `maxSize`, `expireAfterWrite`, `eviction`, `threadSafety` and `recordStats`. The enum values are passed as strings. When `autoMonitor = true`, the plugin calls the 9-argument `create(...)`, which also takes `autoMonitor`, `minHitRate` and `monitorWindow`.

**Static caches (`<clinit>`).** For static `@Memoize` methods, the plugin puts the same setup at the **start** of `<clinit>`, with static fields. If the class has no `<clinit>`, the plugin creates one:

```java
static {
    __memoStaticCacheManager = new MemoCacheManager();
    __memoDispatcher_square_3c8be = MemoDispatcher.create(
        "square_3c8be", 128, -1L, "LRU", "CONCURRENT", false);
    __memoStaticCacheManager.register("square_3c8be", __memoDispatcher_square_3c8be);
    // The original static initializer code follows.
}
```

The setup must come first. A static field initializer, a `static {}` block or an enum constructor can call a memoized static method while `<clinit>` runs.

### 6.7 Phase 4: Method Instrumentation

For each `@Memoize` method, the `MemoizeMethodAdapter` (extending ASM's `AdviceAdapter`) injects code at two points:

**At method entry (`onMethodEnter`):**

```java
// Equivalent Java for: @Memoize public boolean search(int key)

// 1. Build cache key from arguments
CacheKeyWrapper __key = this.__memoDispatcher_search_297da.buildKey(
    new Object[]{ Integer.valueOf(key) }    // box primitive args
);

// 2. Check cache
Object __cached = this.__memoDispatcher_search_297da.getIfCached(__key);

// 3. If hit, unwrap and return
if (__cached != null) {
    return ((Boolean) MemoDispatcher.unwrap(__cached)).booleanValue();
}

// 4. Cache miss: note the start time (0 when timing is off), then run the original body
long __start = this.__memoDispatcher_search_297da.computeStart();
```

**Before each return (`onMethodExit`):**

```java
// Return value is on the stack. Duplicate it, box, and store in cache.
// (The original return value remains on the stack for the actual return.)
this.__memoDispatcher_search_297da.putInCache(__key, Boolean.valueOf(returnValue), __start);
```

For a static method, the dispatcher is read from the static field (`GETSTATIC`) instead of from `this`.

**Primitive handling:** The ASM adapter handles boxing/unboxing for all 8 Java primitive types. It boxes with ASM `GeneratorAdapter.valueOf()`, which emits `Integer.valueOf(i)` and so on (`INVOKESTATIC`). The JDK caches `Boolean`, `Byte`, `Short`, `Integer` and `Long` values from -128 to 127, and `Character` values from 0 to 127. Boxing these values does not allocate.

| Return Type | Boxing | Unboxing |
|-------------|--------|----------|
| `boolean` | `Boolean.valueOf(z)` | `((Boolean)obj).booleanValue()` |
| `int` | `Integer.valueOf(i)` | `((Integer)obj).intValue()` |
| `long` | `Long.valueOf(l)` | `((Long)obj).longValue()` |
| `double` | `Double.valueOf(d)` | `((Double)obj).doubleValue()` |
| `Object` / arrays | no-op | `checkcast` to expected type |
| *(all other primitives handled similarly)* | | |

**For `@CacheInvalidate` methods (`InvalidateMethodAdapter`):**

```java
// Bare @CacheInvalidate (the only form that clears every cache), injected before each return:
if (this.__memoCacheManager != null) {
    this.__memoCacheManager.invalidateAll();
}

// @CacheInvalidate({"search", "length", "describe"}), injected before each return:
if (this.__memoCacheManager != null) {
    this.__memoCacheManager.invalidate(new String[]{"search_297da", "length_8aec2", "describe_a1647"});
}
```

A static method uses `__memoStaticCacheManager`. An instance method that names static and instance caches gets one call for each manager. Each `@Invalidation` target adds one more guarded block. That block calls `invalidate(new String[]{key})` or `invalidateEntry(key, args)`.

**For `@InvalidateCacheEntry` methods (`InvalidateEntryMethodAdapter`):**

```java
// @InvalidateCacheEntry(method = "getTags", keys = {0}), injected before each return:
if (this.__memoCacheManager != null) {
    this.__memoCacheManager.invalidateEntry("getTags_74d6a", new Object[]{ Integer.valueOf(itemId) });
}
```

If the method also has `@CacheInvalidate`, the plugin adds this block to the `InvalidateMethodAdapter` instead, so both annotations take effect.

The null check skips invalidation when the manager field is not set yet. This happens when a constructor, or a superclass constructor, calls the method. A class with only a bare `@CacheInvalidate` still gets a manager field.

## 7. KSP Compile-Time Validation

**Files:**
- [`memoize-ksp/.../MemoizeProcessorProvider.kt`](MORAl/memoize-ksp/src/main/kotlin/io/github/sanadlab/ksp/MemoizeProcessorProvider.kt)
- [`memoize-ksp/.../MemoizeProcessor.kt`](MORAl/memoize-ksp/src/main/kotlin/io/github/sanadlab/ksp/MemoizeProcessor.kt)

The KSP processor runs during Kotlin compilation and validates `@Memoize` usage:

| Check | Severity | Condition |
|-------|----------|-----------|
| Not a function | **Error** | `@Memoize` on a declaration that is not a function |
| Void/Unit return | **Error** | `@Memoize` on a method returning `void`/`Unit` |
| Abstract method | **Error** | `@Memoize` on an `abstract` method |
| Inline function | **Error** | `@Memoize` on a Kotlin `inline` function |
| Non-positive maxSize | **Error** | `maxSize <= 0` in annotation parameters |
| Mutable parameter type | **Warning** | Parameter type not in the immutable set, not a Kotlin `data` class, and no `@CacheKey` annotation |

The immutable type set includes: all Kotlin/Java primitives and wrappers, `String`, `BigDecimal`, `BigInteger`, `UUID`, and Kotlin unsigned types.

The KSP processor is **optional** -- the ASM transformation works without it. It provides earlier, more readable error messages than what would happen at runtime.

## 8. End-to-End Walkthrough

Here is the complete lifecycle of a memoized method, from source code to runtime execution:

### Step 1: Developer writes annotated code

```java
// LinkedList.java
public class LinkedList {
    private Node head;

    @Memoize(maxSize = 64)
    public boolean search(int key) {
        Node current = head;
        while (current != null) {
            if (current.data == key) return true;
            current = current.next;
        }
        return false;
    }

    @CacheInvalidate
    public void insert(int data) {
        // ... modifies head ...
    }
}
```

### Step 2: KSP validates at compile time

The KSP processor checks:
- `search` returns `boolean` (not void) -- OK
- `search` is not abstract -- OK
- `maxSize = 64 > 0` -- OK
- Parameter `int key` is in the immutable set -- OK (no warning)

### Step 3: Javac/Kotlinc compiles to `.class` bytecode

Standard compilation produces `LinkedList.class` with `@Memoize` and `@CacheInvalidate` annotations embedded in the bytecode (retention = CLASS).

### Step 4: AGP calls the Memoize Gradle plugin

During the `transformDebugClassesWithAsm` task, the AGP Instrumentation API passes every project `.class` file through `MemoizeClassVisitorFactory`. In a plain JVM project, the plugin does this step right after `compileJava` or `compileKotlin`.

### Step 5: MemoizeClassVisitor transforms the bytecode

**Pass 1 (Tree API):**
1. Reads `LinkedList.class` into a `ClassNode`
2. Scans: finds `search` has `@Memoize(maxSize=64)`, `insert` has `@CacheInvalidate`
3. Adds fields: `__memoCacheManager`, `__memoDispatcher_search_297da`
4. Patches constructor: inserts `new MemoCacheManager()`, `MemoDispatcher.create("search_297da", 64, -1L, "LRU", "CONCURRENT", false)`, `register()`

**Pass 2 (Visitor API):**
1. Re-reads the modified bytecode
2. For `search`: injects cache-check at entry, cache-store before returns
3. For `insert`: injects `cacheManager.invalidateAll()` before returns

### Step 6: Transformed bytecode is packaged into the APK

The transformed `.class` files are DEXed and included in the APK. The original source remains unchanged.

### Step 7: Runtime execution

```
list.search(10)          // First call
  → buildKey([10])       // Create CacheKeyWrapper for args
  → getIfCached(key)     // Cache miss (returns null)
  → computeStart()       // 0, unless INFO timing is on
  → [original body runs] // Traverses linked list, returns true
  → putInCache(key, true, start) // Store result
  → return true

list.search(10)          // Second call (same args)
  → buildKey([10])       // Same key
  → getIfCached(key)     // Cache HIT (returns the Boolean stored by the first call)
  → unwrap(cached)       // Returns the Boolean
  → return true          // Short-circuits, original body never runs

list.insert(20)          // Mutation
  → [original body runs] // Modifies head
  → cacheManager.invalidateAll()  // Clears search cache

list.search(10)          // After mutation
  → getIfCached(key)     // Cache miss (was invalidated)
  → computeStart()
  → [original body runs] // Re-traverses, returns fresh result
  → putInCache(key, true, start)
  → return true
```


That's it. No call-site changes, no wrapper classes.

### Adding to a plain JVM project

Use the same settings file. In the build file, apply `java` or `kotlin("jvm")` together with the plugin:

```kotlin
plugins {
    java                       // or: kotlin("jvm")
    id("io.github.sanadlab")
}

dependencies {
    implementation("io.github.sanadlab:memoize-annotations:0.1.0")
    implementation("io.github.sanadlab:memoize-runtime:0.1.0")
}
```

The plugin transforms the output of every `JavaCompile` task and of `compileKotlin`. It does not transform Kotlin test sources or Kotlin Multiplatform JVM targets.

## 11. Current Limitations

### Functional limitations

| Limitation | Detail | Workaround |
|------------|--------|------------|
| **JVM mode covers `JavaCompile` and `compileKotlin` only** | In a non-Android project, the plugin rewrites class files after each `JavaCompile` task and after `compileKotlin`. Kotlin test sources (`compileTestKotlin`) and Kotlin Multiplatform JVM targets are not transformed. | Put memoized Kotlin code in the main source set of a Kotlin JVM project. |
| **`CacheScope.CLASS` not implemented** | `CacheScope.CLASS` is defined in the annotation API but not implemented in the ASM transformation. An instance method always gets a per-instance cache. Static methods are supported: a static `@Memoize` method (also a Kotlin top-level or `@JvmStatic` function) gets one cache for its class. For a `@JvmStatic` function in a companion object, the cache is on the companion object. Static methods in interfaces are not supported. | Make the pure function static, or use singleton patterns or application-level DI to share instances. |
| **Interface methods** | Java interface default methods fail the build. Kotlin interface default methods work only through the copies that Kotlin puts in implementing classes (see [Interface and abstract methods](#memoize)). With Kotlin 2.0 and 2.1 `-Xjvm-default=all-compatibility`, and in Java classes that implement a Kotlin interface, the method is not cached. There is no error. Kotlin `-Xjvm-default=all` and `-jvm-default=no-compatibility` fail the build. | Put `@Memoize` on the implementing class. |
| **Kotlin `inline` functions not supported** | Kotlin copies the body of an `inline` function into each caller. The callers never reach the cache. The KSP processor reports an error. | Remove `inline`, or memoize a non-inline function that the inline function calls. |
| **`@CacheKey` field extraction not implemented** | The `@CacheKey("field")` annotation is defined but the ASM transformation does not extract fields. All parameters are used as-is via `Arrays.deepHashCode`. | Ensure parameter types have correct `hashCode()`/`equals()`. Use data classes in Kotlin. |
| **No `onTrimMemory` integration** | The `MemoCacheManager` does not register for Android memory pressure callbacks. | Can be added by registering with `Application.registerComponentCallbacks()`. |
| **No ProGuard/R8 keep rules shipped** | Minified builds may strip runtime classes or renamed fields. | Add keep rules manually or ship them with the library artifact. |

### Technical limitations

| Limitation | Detail |
|------------|--------|
| **Boxing overhead** | Every memoized call boxes primitive arguments into an `Object[]` and builds a `CacheKeyWrapper`. The plugin boxes with `valueOf`, so `Boolean`, `Byte`, and `Short`, `Integer`, `Long` values from -128 to 127 (and `Character` values from 0 to 127) do not allocate. Larger values, `float` and `double` still allocate a box. A miss also boxes the result. |
| **No suspend function support** | Kotlin `suspend` functions compile to state machines at bytecode level. The ASM injection does not handle this. |
| **Method overloading** | Overloads are supported. Each overload gets its own dispatcher field, named with a 5-hex-digit hash of its name and descriptor (`__memoDispatcher_search_297da`). `@CacheInvalidate("name")` clears all overloads with that name. `@Invalidation` and `@InvalidateCacheEntry` use only the first overload with that name. |
| **Debugging** | Breakpoints in memoized methods will hit the injected cache-check bytecode first. The source code does not match the executed bytecode, which can be confusing in debuggers. |
| **Unit test coverage** | Android unit tests (`testDebugUnitTest`) run against the transformed classes (checked with AGP 8.10.1). The JVM and Kotlin JVM test projects also run their tests on transformed classes. Instrumented tests on a device or emulator are not part of the test suites. |
| **Single RETURN in @CacheInvalidate** | The `InvalidateMethodAdapter` injects before every `RETURN`, which works correctly for multiple return points, but `ATHROW` (exception) paths do NOT trigger invalidation. This is intentional: if a mutating method throws, the state may not have changed. |

### Performance characteristics

| Metric | Value |
|--------|-------|
| Cache hit overhead (single int arg) | ~50-80 ns (key construction + HashMap lookup + unboxing) |
| Cache miss overhead | ~80-120 ns (key construction + miss + store) |
| Memory per dispatcher | ~200 bytes base + entries |
| Memory per cached entry | ~80-120 bytes (key wrapper + boxed value + LinkedHashMap node) |
| Build time impact | < 1 second for typical projects. In Android builds, the plugin reads every project class that passes the filter. In JVM builds, it skips classes that do not contain the annotations. |

These values are estimates. No benchmark in this repository measures them.
